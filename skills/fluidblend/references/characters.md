# Characters, rigs and scene

Two scopes that must not be confused:

- **implemented (lot P0)**: `scene.build`, `scene.inspect`, `scene.audit` on stylized bipeds
  generated by the kit;
- **implemented, bounded P1**: local append `shot.build`, `character.inspect`, `rig.validate`,
  `rig.map` on versioned Rigify assets; no rest-pose migration, links or overrides yet.

## What exists: the demo scene

`scene.build` builds a complete, original scene from `shot.json` alone. No external asset, no
download.

```json
{
  "schema_version": "1.0",
  "operation": "scene.build",
  "operation_id": "build-shot010-001",
  "project_id": "demo-studio",
  "target": {"shot_id": "shot010"},
  "parameters": {"preset": "two_characters_prop", "frames": 240, "seed": 0},
  "dry_run": false
}
```

Parameters: `preset` (only value `two_characters_prop`), `frames` (2 to 100000, default 240), `seed`
(default 0). Content produced:

- one FK armature per declared instance, boxes parented to the bones, a colored material per
  instance (blue for the first, orange for the second);
- the prop `lantern-01` parented to the `hand.R` bone of the first character, with a slight offset
  below the hand;
- a 12 x 12 m ground plane, a 35 mm camera oriented towards `look_at`, a sun;
- collections `Characters`, `Props`, `Set`, `Camera`;
- a 48-frame walk cycle per character, looped by a `CYCLES` F-modifier, plus a linear root
  translation on `location[1]` (the -Y axis) over the whole shot duration;
- the shot range and the project frame rate (240 frames at 24 fps on the demo shot).

After saving, the file is **reopened immediately** and inspected: that is the proof that it reopens
and contains what was announced. An audit is run right after; if it fails, the operation fails
(`VALIDATION_FAILED`) instead of publishing a broken scene.

Published artifacts: `shots/<shot>/work/v001/<shot>.blend`, then `scene-summary.json` and
`audit.json` in `reviews/<shot>/<operation_id>/`.

## Rig profile `fluidblend.simple_biped/1`

18 bones, metric scale (about 1.8 m), character facing -Y, walking towards -Y:

```
root
└ pelvis
  ├ spine → chest → neck → head
  │        ├ upper_arm.L → forearm.L → hand.L
  │        └ upper_arm.R → forearm.R → hand.R
  ├ thigh.L → shin.L → foot.L
  └ thigh.R → shin.R → foot.R
```

Rotation mode of the pose bones: `XYZ`. Declared semantic mapping: `root`, `pelvis`, `spine`,
`chest`, `head`, `left_hand` → `hand.L`, `right_hand` → `hand.R`, `left_foot` → `foot.L`,
`right_foot` → `foot.R`. The IK entries (`left_hand_ik`, `right_foot_ik`, and so on) are **null**:
this rig has no IK, no constraints and no pole targets.

Limits to state before making any promise:

- **the characters are not skinned**: the boxes are parented to the bones (`parent_type = BONE`).
  There is no Armature modifier, no vertex group and no weight;
- no face, no shape keys, no fingers;
- global translation lives on the armature object (`location[1]`), not on the `root` bone;
- a "sliding foot" cannot be fixed in P0: `contact_lock` is a P1 tool.

## Identity and custom properties

The kit writes `fluidblend_*` properties so it can find its objects without relying on names:

| Holder | Keys |
| --- | --- |
| Scene | `fluidblend_project_id`, `fluidblend_shot_id`, `fluidblend_revision`, `fluidblend_runtime` |
| Armature | `fluidblend_instance_id`, `fluidblend_asset_id`, `fluidblend_rig_profile`, `fluidblend_kind` (`character`) |
| Box | `fluidblend_part_of` |
| Prop | `fluidblend_instance_id`, `fluidblend_asset_id`, `fluidblend_kind` (`prop`), `fluidblend_holder`, `fluidblend_attach_bone` |
| Action | `fluidblend_clip_id`, `fluidblend_instance_id`, `fluidblend_cycle_frames`, `fluidblend_rig_profile`, `fluidblend_root_motion` |

These keys are exported into the GLB (`export_extras=True`): a `fluidblend_instance_id` survives the
glTF round trip.

## Inspecting

```powershell
fluidblend run --project . --operation requests/scene-inspect.json
```

`scene.inspect` accepts `include_actions` (default `true`) and `include_bones` (default `false`), and
publishes `inspect.json` in `reviews/<shot>/<operation_id>/`: Blender version, scene identity, render
and range settings, counters (objects, meshes, armatures, actions, materials, collections,
libraries, images), the list of objects with parent, parent bone, transform, assigned action and
slot, the list of instances, and missing external files.

## Auditing

`scene.audit` reports, it never fixes. Checks covered:

| Code | Severity | Detects |
| --- | --- | --- |
| `NO_CAMERA` | error | no active camera |
| `BAD_FRAME_RANGE` | error | `frame_end < frame_start` |
| `BAD_FPS` | error | zero frame rate |
| `NON_FINITE_TRANSFORM` | error | NaN or Inf on location, rotation or scale |
| `MISSING_PARENT_BONE` | error | object parented to a missing bone |
| `MISSING_FILE` | error | missing external reference |
| `NON_FINITE_KEY` | error | NaN or Inf key in an Action |
| `ACTION_WITHOUT_SLOT` | error | Action assigned without a slot |
| `ZERO_SCALE` | warning | near-zero scale |
| `SUFFIXED_NAME` | warning | name ending in `.NNN` without `fluidblend_instance_id` (accidental duplicate?) |
| `EMPTY_ACTION` | warning | Action with no key |
| `KEYS_FAR_OUT_OF_RANGE` | warning | keys more than 1000 frames outside the range |
| `INSTANCE_WITHOUT_ACTION` | warning | character without an Action |

Not covered, and the report says so: geometric intersections, skinning weights, cyclic constraints.
Do not present a passing audit as an artistic validation.

## Versioned Rigify characters

Use a project-local manifest matching `schemas/asset.json`: asset id/version, blend path/hash,
license and license path, object names, armature, rig profile. `shot.build` accepts
`assets: [{manifest_path, instance_id, location, rotation_z}]` (metres, radians; placement of the
instance root at import) and `import_mode: "append"` only.
Do not bypass hash/license admission or apply transforms to a skinned character.

A **prop** uses the same manifest with `kind: "prop"`, `root_object` (an unparented non-armature
object among `objects`), no `armature`/`rig_profile`, and `grips`: named points in the root's local
space, `primary` mandatory, `secondary` needed for a hand-off. Manifests without `kind` stay
characters. The profile gains four measurement roles (`left/right_foot_deform`,
`left/right_hand_deform`): a `rig-profile.json` mapped before they existed must be mapped again
before `walk`, `take_prop` or `give_prop`, which answer `RIG_MAPPING_REQUIRED` otherwise.

Run `character.inspect` with target shot and instance; then `rig.map` with the published
`inspection_path`. Evidence must match the current revision. The output `rig-profile.json`
contains semantic controls, explicit nulls and missing controls. Pass its path to
`rig.validate` as `profile_path`. The built-in profile is `rigify/0.6.10`; mapping overrides
use `controls: {semantic_role: actual_bone_name}`. Missing controls are never guessed.

The Vitruvian CC0 fixture tests arms raised, bent elbow/knee, squat and torso twist, reports
uninfluenced vertices and scale problems, and renders five deformation views. These checks
prove finite responsive skin, not anatomical quality or foot contact. CharMorph code remains
external. Rest-pose, hierarchy or scale correction requires an explicit migration, not an
in-place transform. Rig profiles are published in the operation's reviews directory.
