# Installation

Reference machine: Windows 11, PowerShell 7, Blender 5.2.2 LTS, uv. The kit performs no global
installation, and none at all without explicit approval.

## 1. Prerequisites

| Component | Version | Required | Check |
| --- | --- | --- | --- |
| Windows | 11 | yes | the only system tested |
| PowerShell | 7+ | yes | `$PSVersionTable.PSVersion` |
| uv | 0.9+ | yes | `uv --version` |
| Python | 3.13 | yes | provided by `uv sync --python 3.13` |
| Blender | **5.2.x LTS** | yes for any scene operation | `fluidblend doctor` |
| FFmpeg and ffprobe | 8.x | for video previews and `film.assemble` | `fluidblend doctor` |
| glTF-Validator | 2.0.0-dev.3.10 | recommended; when absent, Khronos validation is `not_run` | `fluidblend doctor` |
| Godot | 4.7.2 | lot 4 only; detected, not exercised by the kit | not required here |
| Rhubarb | 1.14.0 | lot 4 only; detected, not exercised by the kit | not required here |
| MCP for Blender add-on | add-on 1.7 (package 2.0.0) | live mode only; requires a GUI Blender session | not required here |
| fluidblend runtime add-on | shipped with the kit | live mode only; installed on request from the kit | `fluidblend runtime status` |

If `uv` comes from another application (Langflow Desktop, for instance), `doctor` reports it.
Installing a standalone `uv` is recommended: `winget install astral-sh.uv`.

## 2. Prepare the kit

```powershell
cd C:\Tafor\Projet\skills\fluidblend
uv sync --python 3.13
```

`uv sync` creates a virtual environment local to the kit. Nothing is installed globally.

Quick check:

```powershell
uv run fluidblend --version
uv run fluidblend ops --all
```

## 3. Guided diagnostic

```powershell
.\scripts\bootstrap.ps1
.\scripts\bootstrap.ps1 -Project "D:\Projects\My Film" -Install
```

The script chains `uv sync`, `fluidblend doctor --write-lock dependencies.lock.json`,
`fluidblend schema check` and the unit tests, then **lists** the missing dependencies together with
the suggested installation command. Without `-Install`, nothing is installed. With `-Install`, each
`winget` installation is offered one at a time with a confirmation. `-SkipTests` skips the tests.

Known suggestions:

| Capability | Suggestion |
| --- | --- |
| `blender.batch` | `winget install BlenderFoundation.Blender`, or set `blender_executable` |
| `video.ffmpeg` | `winget install Gyan.FFmpeg` |
| `gltf.khronos_validator` | official Khronos `gltf_validator` 2.0.0-dev.3.10 win64 archive (Apache-2.0), then `gltf_validator_executable` |
| `game.godot` | `winget install --id GodotEngine.GodotEngine --version 4.7.2 --exact` |
| `audio.rhubarb` | `Rhubarb-Lip-Sync-1.14.0-Windows.zip` archive (MIT), then `rhubarb_executable` |
| `blender.mcp_addon` | `uvx mcp-for-blender install-addon`, then enable it in Blender 5.2 |

Executable paths are set in `<project>/config/local.json`, a machine-specific file that is not
versioned and holds no secret.

## 3 bis. External tools installed on approval

Binaries downloaded on request live in `%LOCALAPPDATA%\fluidblend\tools\<tool>\` (use the
`FLUIDBLEND_TOOLS_DIR` variable to change the location). No PATH entry is added, no system
installation is performed. Discovery order for each tool: path declared in `config/local.json` →
PATH → user tools directory → known Windows installers (`Program Files`, `Program Files (x86)`,
`%LOCALAPPDATA%\Programs`, winget packages). For Godot, the most recent version found is kept,
preferring the `_console` variant (usable stdout in headless mode).

| Tool | Verified source | Expected location |
| --- | --- | --- |
| glTF-Validator 2.0.0-dev.3.10 (Apache-2.0) | `gltf_validator-2.0.0-dev.3.10-win64.zip` (GitHub KhronosGroup, SHA-256 `C5068F51…202C`) | `tools\gltf_validator\gltf_validator.exe` |
| Rhubarb Lip Sync 1.14.0 (MIT) | `Rhubarb-Lip-Sync-1.14.0-Windows.zip` (GitHub DanielSWolf, SHA-256 `62FA416A…1FE3`) | `tools\rhubarb\Rhubarb-Lip-Sync-1.14.0-Windows\rhubarb.exe` |
| Godot 4.7.2 stable (MIT) | official installer | `C:\Program Files (x86)\Godot\Godot_v4.7.2-stable_win64_console.exe` (or any recognised folder) |
| MCP for Blender (add-on 1.7, protocol 7, MIT) | `uvx --python 3.11 mcp-for-blender install-addon` | `%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\blender_mcp.py`, enabled in the preferences |

`fluidblend doctor --write-lock dependencies.lock.json` records the versions, paths and hashes
observed.

### Live mode (MCP) in practice

Live mode lets four operations — `scene.inspect`, `scene.audit`, `animation.retime`,
`scene.checkpoint` — run inside the Blender session you have open. Batch mode needs none of this.

1. **MCP configuration.** The kit ships a `.mcp.json` (Claude Code project scope) generated by
   `fluidblend client-config --client claude`: `uvx --python 3.11 mcp-for-blender --host localhost
   --port 9876`, safe mode on, telemetry off. For a production project:
   `scripts/install-skill.ps1 -Target <project> -WithMcp`. The server name must match
   `mcp.server_name` in `config/local.json` (`blender` by default).
2. **MCP add-on**, installed on approval: `uvx --python 3.11 mcp-for-blender install-addon`, then
   enable it in the Blender 5.2 preferences.
3. **Runtime add-on of the kit** — required for live mode, and only for it:

   ```powershell
   uv run fluidblend runtime install --enable
   uv run fluidblend runtime status
   ```

   `install` copies `blender_runtime/fluidblend_runtime/` into
   `%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\fluidblend_runtime\` with a
   `RUNTIME_MANIFEST.json` (version and hash of the Python tree), and `--enable` enables it
   headlessly in the user preferences. The add-on has no interface: it registers the three operators
   the engine calls. Re-run this command after every kit update — `runtime status` and
   `fluidblend doctor` (capability `blender.runtime_addon`) exit 2 and report `incompatible` when
   the installed hash no longer matches the kit.
4. **Open Blender 5.2 in its graphical interface**: the MCP add-on refuses `--background` and starts
   its socket server on `localhost:9876` as soon as the session loads. Use the *MCP for Blender*
   side panel to stop it or change the port.
5. **Check the session**:

   ```powershell
   uv run fluidblend live status --project "D:\Projects\My Film"
   uv run fluidblend doctor --live --project "D:\Projects\My Film"
   ```

   `live status` prints the open file, the project, the shot, the revision, the dirty flag and both
   versions; it exits 2 when the session is unreachable. Without an open GUI session,
   `blender.mcp_live` stays `unverified`: that is normal, batch mode does not need it.
6. **Run an operation**:

   ```powershell
   uv run fluidblend run --mode live --project . --operation requests/animation-retime.json
   ```

   The engine refuses (exit 3) if the open file is not the shot's latest work version or if the
   scene has unsaved changes. Save or revert in Blender, then retry.

The socket is not authenticated: stay on `localhost` and never open the port. The runtime add-on
stays enabled in your Blender profile until you delete its folder — see `docs/security.md`. Live
mode is covered by acceptance scenarios L01 to L05; live reading through `doctor --live` by A03.

## 4. Graft the skill into a project

```powershell
.\scripts\install-skill.ps1 -Target "D:\Projects\My Film" -Client both
.\scripts\install-skill.ps1 -Target "D:\Projects\My Film" -Client both -WithMcp
.\scripts\install-skill.ps1 -Target "D:\Projects\My Film" -Client claude -Force
```

| Parameter | Effect |
| --- | --- |
| `-Target` | root of the target project, an existing folder |
| `-Client` | `claude`, `codex` or `both` (default) |
| `-WithMcp` | merges a `blender` entry into `<Target>\.mcp.json` |
| `-Force` | replaces an existing copy that differs |

Destinations:

- Claude Code: `<project>\.claude\skills\fluidblend\SKILL.md`
- Codex: `<project>\.agents\skills\fluidblend\SKILL.md`

The script **never writes into `~/.claude` or `~/.codex`**: the installation is local to the
project. It compares the trees by hash: an identical copy is left alone, a different copy is kept
unless `-Force` is given. Finally it writes `kit-path.txt` into the copy, which lets the wrapper
`skills/fluidblend/scripts/fluidblend.ps1` find the kit again.

`-WithMcp` calls `fluidblend client-config --client claude --write <Target>\.mcp.json`. That only
generates a configuration: the MCP add-on and the kit's runtime add-on still have to be installed
separately, after approval (see the live mode section above), and live mode requires a GUI Blender
session.

## 5. Create a production project

```powershell
uv run --project <kit> fluidblend init --path "D:\Projects\My Film" --profile film --project-id my-film --dry-run
uv run --project <kit> fluidblend init --path "D:\Projects\My Film" --profile film --project-id my-film
uv run --project <kit> fluidblend doctor --project "D:\Projects\My Film" --json
```

`init` is idempotent: run again on an existing project, it completes it without overwriting anything
and reports the conflicts. Paths containing spaces and accents are supported.

## 6. Day-to-day CLI usage

Two equivalent forms:

```powershell
uv run --project "C:\Tafor\Projet\skills\fluidblend" fluidblend inspect --project . --json
.\.claude\skills\fluidblend\scripts\fluidblend.ps1 inspect --project . --json
```

The wrapper resolves the kit root in this order: `$env:FLUIDBLEND_HOME`, the `kit-path.txt` written
by the installer, then walking up to a `pyproject.toml` accompanied by `blender_runtime/`. To set
`FLUIDBLEND_HOME` permanently:

```powershell
[Environment]::SetEnvironmentVariable('FLUIDBLEND_HOME', 'C:\Tafor\Projet\skills\fluidblend', 'User')
```

## 7. Tests

```powershell
uv run pytest tests/unit -q
uv run pytest tests -q
uv run pytest tests --acceptance-report docs/acceptance-reports/latest-p0
```

Tests marked `blender` are skipped automatically and marked `not_run` if no Blender 5.2 is detected;
they are then not counted as passed. The live scenarios L01 to L05 additionally need the MCP add-on,
`uvx`, the runtime add-on and port 9876 free: each of them opens and closes its own Blender GUI
session, and declares itself `not_run` otherwise. The acceptance report is written in `.json` and
`.md`, giving for each scenario — A01 to A13 and L01 to L05 — its status, duration and notes.

## Uninstalling

Delete `<project>\.claude\skills\fluidblend` and `<project>\.agents\skills\fluidblend`, as well as
the `blender` entry of `<project>\.mcp.json` if it was added. If live mode was used, also delete
`%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\fluidblend_runtime\` and disable the
add-on in the Blender preferences. The kit itself is removed by deleting its folder; apart from that
add-on folder and the user tools directory, nothing was written anywhere else on the system.
